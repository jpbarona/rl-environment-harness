## Isolation (verified against installed OpenCode v2.0.18, 2026-10-08)

Verified by direct experiment (not documentation alone):

- Setting `HOME`, `XDG_DATA_HOME`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`, and `XDG_STATE_HOME` to temporary directories redirects all OpenCode state. Experiment: `HOME=$T XDG_DATA_HOME=$T/data XDG_CONFIG_HOME=$T/cfg opencode session list --standalone` created only `$T/.local/state/opencode`, `$T/cfg/opencode`, `$T/data/opencode/{repos,shell,log}`, and `$T/.cache/opencode`. No state was written to the real user home. [Evidence: directory listing of the temp dir in this session.]
- `~/.opencode/bin/opencode run --help` documents `--standalone` ("Run with a private server instead of the background service") and `--auto` ("Auto-approve permissions"), both used for isolated non-interactive runs. [Evidence: help output in this session.]
- `OPENCODE_CONFIG=<path>` loads a specific config file; GitHub issue 4526/PR 8963 document `OPENCODE_DB` and `OPENCODE_CONFIG_DIR` overrides. `OPENCODE_DB` is documented upstream but not yet exercised in this project; treat it as unverified until used. [Evidence: https://github.com/anomalyco/opencode/issues/4526 ; docs page /docs/config/.]

## Plugin API (verified against installed OpenCode v2.0.18)

- The published hook list includes `event`, `tool.execute.before`, and `tool.execute.after`. The implemented plugin (generated by `src/capture/e2e.ts`) uses the `event` hook and `tool.execute.after` only. [Citation: https://opencode.ai/docs/plugins/, retrieved 2026-10-08.]
- The published hook list has no hook that fires between "user submits a prompt" and "first provider request". The capture barrier is therefore anchored in the recorder proxy, which holds the first request of a turn until the workspace capture commits, and fails closed with an HTTP 502 on capture failure. The plugin records session and tool events only. [Evidence: docs page hook list; design decision recorded in Entry 008.]
